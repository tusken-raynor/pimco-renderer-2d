Overview:

  All types are classified as ConfiguratorObjects, Sub-Types, or Data objects. Each 
  type classified as a ConfiguratorObject has a unique identifier and other mutual 
  properties such as 'type' and 'name'. 
  
  The 'type' property value of each ConfiguratorObject always matches the type's 
  name, with the two exceptions of SeriesInfo and LeatherInfo. This is used to query 
  off of and identify the type of a data object both from the database and in 
  run-time. 

  Sub-Types are simply used to prevent redundancy when multiple types have 
  properties with identical structures. Instead of redefining the property structure 
  on each type, a Sub-Type is created which can be easily referenced multiple times.

  Data object types represent common structures that contain data for different
  Vue components. A typical example are popups, which all required a specific
  format of data to be passed to the Vue component to then render the popup.

  Below is defined each type from the three categories.


CATEGORY: ConfiguratorObjects

  Another property mutual to ConfiguratorObjects is 'comment', which is
  used soley to give helpful information about the ConfiguratorObject, since json
  does not allow for lines of commentary.

  A property common to most ConfiguratorObjects is 'nickname'. This property is
  always optional, but when provided, it is typically displayed in place of the
  literal name of the ConfiguratorObject within the app usually for the purpose of
  showing a condensed name. 

  Another property common to most ConfiguratorObjects is 'info'. This property has 
  different structures depending on the specific type of attribute in question. It 
  can be an ID referencing a Data object, it can be of a structure that is a Data 
  object type, a string of text/HTML markup to be rendered, or the structure may be 
  uniquely defined for that ConfiguratorObject's type.

TYPE: Product

  The Product is the basis for all the 

 -The property called 'models' is an Array listing the IDs of the available models.
 -The 'primaryclass' property determines the main class used for filtering models on 
  the patterns page. (See 'classes' property on the Model type).
 -Each product must specify a base price using the 'baseprice' property.
 -The configurator app currently support three modes: 'blank', 'color', and 
  'series'. The 'blank' mode means the user is designing from scratch, 'color' means 
  they're using Colorplay to start a design, and 'series' means they are designing
  the product using a series, or product line. The 'blank' mode is always required
  while the other two are optional. 
 -If the product needs to support series, a property can be included which lists the
  unique IDs of the series for the product.
 -Each product is resonsible for providing the generic type and data displayed on
  the start page for designing that product. This is nested within an object under 
  property called 'startpage'.

TYPE: Model

 -The 'classes' property holds and object which defines metrics that will be used to
  filter through models on the patterns page. 
 -The 'attributes' property lists the IDs of the attributes for that model.
 -The 'wcvalue' property defines the value for the woocommerce addon value that 
  represents that specific model.

ABSTRACT TYPE: Attribute

 -The 'component' property is the name of the Vue component that will be used to
  render the attribute options. Each attribute type will have its own component.
 -The 'notify' property is of StandardPopupInfo type. If this property is included on 
  an attribute, a popup will appear when the portion in the app for that attribute is
  reached.
 -The 'wcname' property is used to define the name of the addon representing that
  particular attribute. It is common to leave the order number that is present on all 
  woocommerce addon names absent from the 'wcname' property on the attribute because 
  attributes may be reused during the design portion of the product and may not have 
  the same ordering between the addons in woocommerce. The order number will be 
  properly added at checkout to add the product to cart.
 -There are some attributes which reference options that themselves can reference
  sub-options. These attributes have an 'options' property with sub-properties that
  define nessesary information for the immediate options it references, and 
  sometimes for sub-options as well.
 -One of these sub-properties is 'key', which gives name to what the sub-options are
  being selected for. 
 -Another sub-property is 'options' which lists the IDs referencing the options.
 -Another sub-property is 'default'. This defines an ID for an option and will 
  designate a default value for start up if an ID is provided.
 -Another sub-property is 'required', which let's the app know if a selection is
  required to checkout. Selection for each attribute is required by default.
 -Another sub-property is 'ignore'. This property takes a boolean value and can 
  be used to communicate to the Structure builder to completely ignore this 
  layer in the options chain. This is useful if an option is being used to house
  sub-options but itself is unnessesary to the process. 
 -Another sub-property is 'pimcovalue' which indicates the listed options as being 
  the supplier of the value that the product image needs.
 -Another sub-property is 'wcname', which is a stand in for the 'wcname' property 
  mentioned above. This property is moved within the 'options' property to better 
  manage name scoping. When this is the case, this sub-property can contain the 
  substring '$scope$', which will be replaced when the Selections Structure is 
  built by so that the nested structure of the app's data can be properly 
  transformed to map with the woocommerce product's linear structure. It's really
  complicated, so just send me a email -- powell.samwell@gmail.com -- if it doesn't 
  make any sense.
 -Another sub-property is 'wcscope', which is used to replace the '$scope$'
  substring in the 'wcname' property of the closest attribute up the options chain.
  In this case this is still that attribute.
 -Attributes which reference sub-options have a 'pimco' property which lists the IDs 
  referencing the image components that have options under the attribute are 
  responsible for coloring/texturing. PIMCO stands for Product IMage COmponent.

TYPE: Basic Attribute, Color Attribute

 -The 'options' property lists the IDs of the options under that attribute.
 -The 'default' property specifies an ID that becomes the default selected option
  on start up.

TYPE: ParallelAttribute 

 -Has become obsolete now.

TYPE: ComplexAttribute

 -This type has the ability to house sub-attributes which are defined in the
  'attributes' property. The sub-attributes must be of the ComplexSubAttribute type.

TYPE: ComplexSubAttribute

 -An important property is 'options', which is discussed in great detail under the
  ABSTRACT TYPE: Attribute section.
 -The 'leatherguide' property gives a boolean value to indicate to the configurator 
  to render a button that open the leather guide. It is only meant to be present on
  attributes that contains ComplexLeatherOptions as sub-options somewhere along its
  options chain. 

TYPE: GrandAttribute

 -This type has the ability to house sub-attributes which are defined in the
  'attributes' property. The sub-attributes must be of the GrandSubAttribute type.

TYPE: GrandSubAttribute 

 -The 'subtitle' property can be used to render a sub title under the main title the
  attribute dropdown, and is visible when the dropdown is opened.
 -This sub-attribute type is unique as in place of defining sub-options, it can 
  instead reference sub-attributes of its own. The sub-attributes are of the type
  GrandAddonAttribute. The property to reference the addon attributes is simply
  'attributes'. 
 -The 'options' property is structured and works the same way as mentioned above in
  the ABSTRACT TYPE: Attribute section. It is IMPORTANT to note that the 'options'
  property and the 'attributes' property are mutually exclusive to each other for
  this type, and that rule will be enforced at run-time.

TYPE: GrandAddonAttribute 

 -The 'options' property is structured and works the same way as mentioned above in
  the ABSTRACT TYPE: Attribute section.
 -The 'image' property has a value of type ImageData, or can simply be a URL substring
  for the image src. If provided, an image of the addon will render above the listed 
  options.

ABSTRACT TYPE: Option 

 -The 'upcharge' property is used to specify when that option is selected, the app
  must add the value to the baseprice. The value of this property is of number type,
  representing a dollar value. The type can also be a string, and when a percent 
  symbol is added after the number it is calculated as a percentage of the baseprice.
 -The 'restrict' property can be included on an option to define one or an array of 
  option restrictions whenever that option is selected. This can be used to remove
  certain options in other parts of the configurator when selection of a certain
  option requires removal of those options as part of the available scheme.
 -The 'apply' property allows for an option to set a selection, or multiple 
  selections, elsewhere in the configurator app upon its own selection.
 -The property called 'wcvalue' represents the name of the woocommerce addon value
  of the product in woocommerce. It is common to leave the order number that is 
  present on all woocommerce addon values absent from that 'wcvalue' property on an
  option because options are frequently reused in the app for different attributes
  and may not have the same ordering between the addons in woocommerce. The order
  number will be properly added at checkout to add the product to cart.
 -Some option types have a property called 'pimcosettings'. This is an object of the
  ProductImageComponentSettings type structure.

TYPE: BasicOption 

 -The 'graphic' property is of the type ImageData, but can just be an image URL 
  string. 

TYPE: ColorOption

 -The 'color' property must be a string value of either a hex code, proper RGB(A) 
  color string, or a valid css color name. 
 -The property 'altcolor' can be used to give a secondary color value if the 
  presentation color doesn't match the needed color for the product image.

TYPE: ComplexSwatchOption, ComplexChromaOption

 -The property 'swatchtype' can either have the value of 'color' or 'image'. When
  the 'swatchtype' property is defined, the 'swatch' property must have the 
  proper value tpye correlating to whether it is an image or a color. The
  ComplexChromaOption type is identical to ComplexSwatchOption other than the
  'swatchtype' property will always have the value of 'color'. This near 
  identical version was created to that certain options that were specifically
  designed to be color could be queried off of in the database.
 -The property 'swatch' must be a string value of either a hex code, proper RGB(A) 
  color string, or a valid css color name. It also supports image information of
  type ImageData or an image URL string.

TYPE: ComplexImageOption 

  This type of option is fundamentally different than ComplexSwatchOption in how

TYPE: ComplexLeatherOption

 -The 'usenickname' property was created to appease the designs of Sir Curtis 
  Hemmert. There were inconsistencies in the design of the leather guide for
  the proper name, or the nickname was to be applied. This property allows for
  control over that very issue. If the property is not included on the option,
  its value will be defaulted to 'true'.
 -The 'prefix' property can be used to specifiy the leather name prefix on the
  leather guide page. If property is absent, the name of the series that the 
  leather belongs to will be used.
 -The 'info' property on this option type is an ID referencing a LeatherInfo
  object that houses more data for that particualar leather.

TYPE: ComplexColorsOption

 -The 'comrades' property lists IDs referencing other ComplexColorsOption 
  options and lay them parallel to the options chain structure eneabling the
  option that lists the 'comrades' to support multiple color slots. It's kinda
  complicated, so just send me a email -- powell.samwell@gmail.com -- if it 
  doesn't make any sense. 
 -ComplexColorOption options that are referenced as comrades instead will have
  a property called 'source', which is just the ID referencing back to the main
  option that contains the 'comrades' property.
 -The property 'icon' allows for an icon or image to be rendered for the option.
  If left off, the option will render with just the name.

TYPE: ComplexTextOption

 -The 'text' property holds the text value that gets entered into the input. It 
  will be applied programatically when a value is entered. This property should 
  either not be included on the option or should be given an empty string only. 
  Do not use this property to set the default value in the text field. Use the 
  'default' property for that.
 -The 'placeholder' property sets the placeholder attribute for the text input
  element.
 -The 'maxlength' property sets the maxlength attribute for the text input
  element.
 -The 'default' property gives the text input element a start value.

TYPE: GrandAddonOption

 -The 'boolean' property is used to indicate if which option means the user wants

TYPE: LeatherInfo 

 -The 'icon' property was intended to define the more basic icon for the leather,
  which is just the animal.
 -The 'fullicon' property was intended to define the more complex icon, which is 
  the animal and the name of the leather together.
 -The 'highlights' property is used to list the strong points, or highlights of
  the leather on the leather guide.
 -The 'description' property is used to add a description in the leather guide.
 -The 'images' property is used to define the images for the image gallery in 
  the leather guide for that leather. It can define both the thumbnails and the
  preview images.
 -The 'breakin' property is used to define the break-in level for the leather.
 -The 'weight' property is used to define the weight of the leather.
 -The 'properties' property defines the properties of the leather used for the
  leather comparison page. The metrics for those properties are defined in the
  misc.json file.

TYPE: SeriesInfo

 -The 'thumbnail' property defines the thumbnail image used in the list of 
  series to design from.
 -The 'preview' property defines the preview image that appears once a 
  series is clicked on the start page.
 -The 'spimage' property defines the spin image data that, if included, will
  take the place of the 'preview' image once all the images used for the spin
  image are downloaded.
 -The 'models' property defines the models that are used to filter on the 
  patterns page.
 -The 'leathers' property defines the leather that are included in the series.
 -The 'breakin' property defines the break-in level for products from that
  series if a propery break-in level cannot be computed using the leathers 
  that are a part of the series.
 -The 'weight' property defines the weight for products from that series if a 
  propery weight cannot be computed using the leathers that are a part of the 
  series.
 -The 'restrict' property defines the options and attributes that must be
  restricted within that series.
 -The 'insert' property defines the attributes and options that are to be
  added into the build process and where they get added into.
 -The 'wcnote' property specifies the name of the woocommerce addon where a
  note can be added specific to that series for use by the customer and/or
  the manufacturer. The value of the note is also defined within the property
  as well.

TYPE: ProductImageComponentRegion

 -The 'frames' property is an array of ProductImageComponentFrame type objects. 
  These objects contain that mask image and optional bolt-on image for each
  particualar frame. Each frame is meant to represent an angle or view of the
  product.
 -The 'fill' property, if included, references other image components that
  will use the same color/texture value until they have their own values.

TYPE: ConfiguratorRestriction

 -The 'id' property is the id of the attribute or option to be restricted.
 -The 'path' property is the sequence of property names and can be used to

TYPE: OptionApplication

 -The 'id' property is the id of the option to be set as the selection.
 -The 'path' property is the sequence of property names to set the option

TYPE: AlterationDesignation

 -The 'id' property is the id of the option to be restricted or inserted.
 -The 'parent' property is the id of the parent where the option is being,
  or is going to be referenced.

CATEGORY: Data Objects

TYPE: StandardPopupInfo

  This type is used to supply data to the StandardPopup component to make it
  render.

 -The 'index' property is used so that the popup can be indexed if you only 
  want it to popup once instead of each time it's triggere event happens.
 -The 'delay' property specifies a wait time between when the trigger event
  happens to show the popup, and when the popup actually appears.

TYPE: SpecialPopupInfo

 -The 'mode' property specifies between the two modes that are available. The
  'confirm' mode is similar to Javascript's confirm function. The 'share' mode
  shows the user an interface to copy the share link for the build session, or
  social media links to share them on social media.
 -The property called 'confirm' can be used in the confirm mode to supply an 
  alternate label for the confirm button, and a callback function to run when
  confirm is clicked. 
 -The property called 'cancel' can be used in the confirm mode to supply an 
  alternate label for the cancel button, and a callback function to run when
  cancel is clicked. 

TYPE: ImageData

  This type is used as a simple way to define all the possible information for 
  an img element encased in one object.

TYPE: ProductImageComponentFrame

  Product image components must reference a new mask, and possible a new base 
  image and a possible highlight image.

 -The 'mask' property has a value of ImageData or string type, and determines 
  the mask for that layer of a particular frame.
 -The 'image' property has a value of ImageData or string type, and determines 
  the base image for that layer of a particular frame. If a base image is not
  given, it will default to the base image of the product model.
 -The 'highlights' property is an object that contains sub-properties which 
  can hold information for two highlight images. The properties support defining
  an image url, alpha or opacity, and blend mode for both highlights.
 -The 'order' property is used to control the render order of the image 
  component layers.

TYPE: ProductImageComponentSettings 

 -The 'mode' property determines if the image component is to use a color or
  a texture image.
 -The 'color' property holds a hex, rgb, or proper css color value. Will be
  used when the 'mode' proptery value is 'color'. The value of this property
  may also be the name of a property of the Option it's from to use the value
  of that property. Make sure to wrap the property name in '$' at the end and 
  beginning to indicate that an option perperty value is to be used. This 
  property is mutually exclusive to the 'texture' property.
 -The 'texture' property holds a ImageData or string type value. Will be used 
  when the 'mode' proptery value is 'image'. The value of this property may 
  also be the name of a property of the Option it's from to use the value of 
  that property. Make sure to wrap the property name in '$' at the end and 
  beginning to indicate that an option perperty value is to be used. This 
  property is mutually exclusive to the 'color' property.
 -The 'alpha' property defines what the opacity of the texture or color will 
  be.
 -The 'blend' property defines what type of blend function will be used for
  blending the texture or color with the base image.
 -The 'altbaseimage' property allows for the base image of the pimco to have
  a string appended to the name of the current image url. This allows for the
  color/texture aspect of the pimco to determine the base image in tandem with
  the frame, to allow for more flexability if the color/texture needs it. This
  requires that the image files with the generated names exist or it will 
  cause issues.
